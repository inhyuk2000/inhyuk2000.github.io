## 애자일소다 취업을 준비하며..

애자일소다의 생성형 AI 데이터 사이언티스트 직무에 지원했고, 서류 전형 합격 소식을 받았다. 평소 관심을 가져온 {{% high_mark %}}**AI Agent와 데이터 사이언스가 결합된 직무라는 점**{{% /high_mark %}}에서 특히 매력을 느꼈고, 그동안 연구실에서 진행했던 경험과도 잘 맞는다고 생각했다.

## 서류 합격 후 실무 면접

면접에서 받았던 주요 질문과 당시 답변을 복기해보면 다음과 같다.

### 0. 자기소개와 지원동기

현재 컴퓨터공학과 4학년 졸업반이며, 일상에서 발견할 수 있는 문제를 정의하고 AI를 활용해 실제 사용자 편의를 높이는 시스템을 만드는 데 관심이 있다고 설명했다.

특히 학부연구생으로 활동하며 문제 정의부터 시스템 설계와 구현, 실험 및 성능 검증까지 경험했고, 이러한 경험이 애자일소다의 생성형 AI 데이터 사이언티스트 직무와 잘 맞는다고 생각해 지원했다고 답변했다.

### 1. 진행했던 프로젝트에 대해서 간단히 설명해보세요.

여러 프로젝트 중 애자일소다의 직무와 가장 관련성이 높고, 개인적으로도 기여도가 높았던 {{% high_mark %}}**'멀티 에이전트 토론을 통한 환각 탐지 및 교정'**{{% /high_mark %}} 연구와 {{% high_mark %}}**'자연어 기반 알림 전송 제어 시스템'**{{% /high_mark %}}을 중심으로 설명했다.

각 프로젝트에서 어떤 문제를 해결하고자 했는지, 시스템을 어떻게 설계했는지, 그리고 내가 어떤 부분을 직접 구현하고 검증했는지를 중심으로 이야기했다.

### 2. 자연어 기반 알림 전송 제어 시스템의 구체적인 동작 로직은 어떻게 되나요?

시스템의 핵심 로직인 '알림 관리자'와 '조건 추출자'의 역할을 중심으로 설명했다.

사용자의 자연어 요청에서 시간, 장소, 활동 등의 조건과 대상 애플리케이션 및 키워드를 추출하고, 이를 구조화된 형태로 변환해 알림 관리 로직에 전달하는 전체 흐름을 설명했다.

이전에 학회 발표를 준비하며 포스터와 발표 연습을 반복했던 경험 덕분에 비교적 자연스럽게 설명할 수 있었다.

### 3. 사용자의 자연어 명령을 JSON으로 파싱하는 과정에서 오류가 발생하면 어떻게 처리하나요?

현재 구현한 시스템은 연구용 프로토타입이기 때문에 파싱 오류를 세분화해 처리하는 별도의 예외 처리 로직까지 구현하지는 않았다고 설명했다.

다만 조건 추출 단계에서 각 필드가 가져야 하는 형식과 조건을 구체적으로 정의했고, 올바르지 않은 값이 입력되거나 필요한 필드가 누락된 경우에는 사용자가 다시 입력할 수 있도록 안내하는 형태로 처리했다고 답변했다.

이 질문을 통해 실제 서비스 수준으로 확장하기 위해서는 단순한 프롬프트 제약뿐만 아니라 JSON Schema 검증, 필수 필드 검증, 재시도 로직과 같은 보다 명확한 예외 처리 구조가 필요하겠다는 생각도 들었다.

### 4. '7호선 급행열차 최적 정차역 제안' 프로젝트에 대해서도 설명해주세요.

7호선 급행열차 신설 상황을 가정하고, 급행 정차역을 선정해 이용자의 편익을 높이는 것을 목표로 진행한 프로젝트라고 설명했다.

승하차 인원 및 혼잡도 등을 주요 지표로 설정했고, 독립변수 간 다중공선성을 확인하기 위해 VIF와 PCA를 활용했다. 이후 계층적 클러스터링을 통해 유사한 특성을 가진 역들을 그룹화하고 후보를 축소한 뒤, 슬라이딩 윈도우 방식의 모델링을 적용해 최종 정차역을 선정했다고 설명했다.

### 5. 계층적 클러스터링에 대해서 설명해주세요.

비슷한 특성을 가진 데이터들을 계층적으로 묶어가는 군집화 방법이라고 설명했다.

프로젝트에서는 여러 역의 특성을 기준으로 유사한 역들을 단계적으로 그룹화하고, 이를 통해 전체 역을 몇 개의 특성이 유사한 그룹으로 구분하기 위해 활용했다고 답변했다.

{{% high_mark %}}**당시 답변을 돌아보면 개념 자체는 설명했지만, Agglomerative 방식과 거리 척도, linkage 방식 등 조금 더 구체적인 내용을 함께 설명했다면 더 명확했을 것 같다.**{{% /high_mark %}}

### 6. 다중공선성에 대해서도 설명해주세요.

독립변수들 사이에 높은 상관관계가 존재하면 각 독립변수가 종속변수에 미치는 영향을 개별적으로 해석하기 어려워지고, 회귀계수의 추정이 불안정해질 수 있는 문제라고 설명했다.

프로젝트에서는 이러한 문제를 확인하기 위해 VIF를 활용했고, 일부 변수들의 정보를 축약하기 위한 방법으로 PCA도 함께 적용했다고 답변했다.

이 질문을 통해 데이터 분석 프로젝트에서 사용한 기법을 단순히 '썼다'고 설명하는 것보다, {{% high_mark %}}**왜 해당 기법이 필요했고 어떤 문제를 해결하기 위해 사용했는지를 정확하게 설명하는 것이 중요하다는 점을 다시 느꼈다.**{{% /high_mark %}}

### 7. 저희 회사의 업무 강도가 조금 있는데 이 부분은 괜찮으신가요?

학부연구생으로 활동하면서 동시에 4학년 전공 수업과 여러 프로젝트를 병행했던 경험을 이야기했다.

당시 일정이 쉽지는 않았지만, 새로운 것을 배우고 성장하는 과정에서 큰 의미를 느꼈고 현재도 성장에 대한 욕심이 큰 편이기 때문에 충분히 도전해볼 수 있다고 답변했다.

### 8. 최신 기술이나 트렌드 관련해서 아는 것이 있나요?

학부연구생으로 활동하며 랩 세미나를 통해 다양한 최신 연구를 접했던 경험을 이야기했다.

그중 사용자의 스마트폰 화면과 행동을 이해하고 실제 UI 동작을 수행하는 AI Agent 관련 연구와, 음악이나 주변 환경에 자연스럽게 정보를 전달하는 HCI 관련 연구가 인상 깊었다고 설명했다.

면접관이 기대했던 답변과 완전히 일치했는지는 모르겠지만, 당시 바로 떠오르는 기술 트렌드를 나열하기보다는 실제로 읽고 관심 있게 봤던 연구 사례를 이야기하는 편이 더 낫다고 판단했다.

{{% high_mark %}}**다만 이후에는 Agentic AI, Tool Use, RAG, Memory, Multimodal Agent 등 생성형 AI 분야에서 현재 활발하게 다뤄지는 기술 흐름도 조금 더 체계적으로 정리해둘 필요성**{{% /high_mark %}}을 느꼈다.

### 9. 마지막으로 저희 회사에 대해 궁금한 점 있나요?

생성형 AI 데이터 사이언티스트가 실제 프로젝트를 진행할 때 고객이나 이해관계자의 요구사항을 파악하는 초기 커뮤니케이션 단계부터 직접 참여하는지 궁금하다고 질문했다.

단순히 전달받은 요구사항을 구현하는 것보다 문제를 정의하는 단계에서부터 데이터 사이언티스트가 얼마나 참여하는지가 궁금했기 때문이다.

프로젝트와 상황에 따라 참여 범위가 달라질 수 있다는 답변을 들었다.

### 10. 검증 과정에 대해서 아나요? 통계 관련 지식도 좀 아시나요?

데이터 사이언티스트 직무인 만큼 프로젝트 결과를 어떻게 검증했는지와 통계적 검증 방법에 대한 질문도 받았다.

통계와 관련해서는 아직 충분히 깊게 공부하지 못한 부분이 있다고 솔직하게 답변했고, p-value와 통계적 유의성에 대해 알고 있는 범위에서 설명했다.

면접 이후 다시 생각해보니 단순히 모델 성능이나 결과 수치를 제시하는 것뿐 아니라, 그 차이가 실제로 의미가 있는지 통계적으로 검증하는 과정까지 포함해야 보다 설득력 있는 분석이 된다는 점을 느꼈다.

## 느낀점

이번 면접을 준비하고 실제 질문에 답변하는 과정에서 내가 진행했던 프로젝트를 다시 한번 깊게 돌아볼 수 있었다.

특히 포트폴리오에서 결과 수치만 보여주는 것에 그치지 않고, {{% high_mark %}}**그 결과가 얼마나 신뢰할 수 있는지 검증하는 과정**{{% /high_mark %}}을 조금 더 보강해야겠다는 생각이 들었다.

현재 서비스화하고 있는 '자연어 기반 알림 전송 제어 시스템' 역시 단순히 기능을 구현하는 것에서 끝내지 않고, 실제 사용자 데이터를 기반으로 사용 패턴과 오류 유형을 분석하고 성능을 정량적으로 검증하는 방향으로 발전시켜보고 싶다.

통계와 데이터 분석에 대한 공부 역시 조금 더 필요하다는 것을 느꼈다. 프로젝트를 진행하며 여러 분석 기법을 사용해봤지만, 어떤 기법을 사용했다는 사실보다 왜 해당 기법을 선택했고, 어떤 가정을 기반으로 하며, 결과를 어떻게 해석해야 하는지를 정확하게 이해하는 것이 훨씬 중요했다.

무엇보다 이번 면접에서 가장 크게 느낀 점은 면접 답변 전략이나 말을 잘하는 것보다 {{% high_mark %}}**내가 했던 일을 스스로 얼마나 정확하게 이해하고 있는지가 가장 중요하다는 것**{{% /high_mark %}}이다.

면접관은 이해되지 않는 부분이 있으면 계속해서 질문을 이어갔고, 내가 진행한 프로젝트를 상대방이 이해할 수 있도록 설명하는 것 역시 결국 나의 역할이었다.

앞으로는 프로젝트를 단순히 완성하는 것에서 끝내지 않고, 사용한 기술과 방법론 하나하나에 대해서 왜 사용했는지, 어떤 한계가 있는지, 다른 방법과 비교했을 때 어떤 장단점이 있는지까지 설명할 수 있을 정도로 공부해야겠다.
