## 인프런 멘토링 사전 준비
{{% high_mark %}}**진행 상황**{{% /high_mark %}}

현재 **LLM을 활용한 자연어 기반 알림 전송 제어 시스템** 연구를 현재 서비스화하고 더 발전시키는 과정임.
- 서비스화를 위한 UI / UX 디자인
- 자연어 추출 로직과 추출 결과를 기반으로 사용자 앱과 연동하는 로직을 `FastAPI` + `LangChain` 기반의 AI 백엔드로 분리
- `Code-based Evaluaiton`을 활용하고, `LangSmith` 기반 정확도 평가를 통해 프롬프팅 및 코드 개선 진행중.

또한 기본적인 **ML/DL 기본 개념**과 **통계** 관련 개념 공부를 추가로 진행중임.

{{% high_mark %}}**추후 진행 계획**{{% /high_mark %}}
- **멀티 에이전트 연구** 역시, 그 당시 에 받았던 **결과 신뢰성 검증**, **통계 검증 관련 내용 부족**들을 보완해 서비스화시켜 발전시킬 예정입니다. *(KCC 학회 발표 당시 받았던 피드백)*
- 현재 **NotiLLM** 연구에서 **사용자의 모호한 답변**은 어떤 처리 전략을 가져야 할지에 대한 고민 필요
  - `LangGraph`를 활용한 재질문 및 추가 처리 전략도 고민 필요.

### 진행중인 스케줄대로 Evaluation 이후 AWS 배포를 진행하면 되는가?
- 정리 잘 하기는 했지만, outlier 포인트는 **핵심은 로딩**이므로 {{% high_mark %}}**부하 테스트를 통해 사용자 입장에서 서비스 개선점을 검토**{{% /high_mark %}}하는 게 굉장히 중요함.
  - 실제 사용자 배포 과정 바로 전에 부하 테스트해야 할 필요성이 있을 거 같음.
  - 부하 테스트 목표 설정
    - `p95 latency < 3초` = 전체 요청의 95%가 **3초 이내**에 응답해야 한다 = *"모든 사용자가 서비스에서 가끔 겪는 느린 순간을 5% 이하로 관리한다."*
    - [ {{% high_mark %}}**Outlier Point**{{% /high_mark %}}] **사용자 입장**에서 이용료, 결재 플랜 검토
      > GCP인스턴스 10개 한달 가격은 100만원, API 한달 평균 비용, 서버비용, 인건비 등등 -> 100명이 모두 유료로 결제한다고하면 1인당 2만원의 플랜을 결제해야함... 그러면 만약 나라면 이 가격에 서비스를 사용하지 않을 거 같음..
      
      {{% high_mark %}}**판단 예시**{{% /high_mark %}}
      >  지금 셋팅하고 있는 환경에 더 비용을 최적화하려면 GPT-4o 오픈소스 모델로 Quantization(양자화) 기법을 써서 충분히 줄일 수 있을 것이다.

  - Evaluation Dataset 구축이라면 <u>**"최소 N개 케이스, 카테고리별 커버리지 X% 이상"**</u> 같은 기준이 있어야함
- 서비스는 무조건 **내부 평가**와 **상대 평가**를 함께 진행해야 함.
  > 핵심 기능 A Test를 여러 경쟁 앱들과 비교/분석해서 "어탠션 게임"이라는 키워드 앱은 기존 타사 앱은 필터링하지 못함.
- `(핑크펭귄이론)` 기존 이런 시스템은 안되는데, 우리 시스템은 된다는 거를 대문짝만큼 넣어놔야 함. 
  - 차별점들을 보여주는 그림 자료를 보여주는 게 좋음
- 입력에 대한 출력까지의 과정이 1초, 정말 늦으면 2초까지도 생각해볼 수 있음.
  - `Locust` 라는 부하테스트 툴이 있음. (처음 version 1은 100명 기준으로.) -> 아마 2초 그 이상으로 넘을 거 같음
  - 만약 5초라고 한다면, python library로 코드 한 줄마다 어디가 제일 병목인지 확인해보는 게 필요함.
  - 이 5초를 2초로 바꾸려면, 어디를 최적화해야 하지? load-balancing을 더 잘 해줘야 하나
- `dataset은 어떻게 구성했는지`에 대한 명확한 근거 기반 데이터셋 설정 필요
